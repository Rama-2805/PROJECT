1. EXECUTIVE SUMMARY & SYSTEM TOPOLOGY
================================================================================
SmartCampus AI is an enterprise-grade, privacy-first computer vision and campus
management ecosystem designed to automate multi-student classroom attendance,
biometric face enrollment, academic scheduling, behavior analysis, and IoT device
orchestration with zero cloud reliance for sensitive biometric data.

Key Architectural Invariants:
• 1 Physical Person = 1 Identity Candidate: Eliminates over-clustering and false
  merging using multi-evidence ArcFace vector consolidation.
• Two-Stage Video Processing: Frame sampling & IoU temporal tracking (Stage 1)
  followed by deferred batch ArcFace embedding & HDBSCAN clustering (Stage 2).
• Privacy-Centric Local Execution: 512-D L2-normalized vectors stored in local
  FAISS indexes; raw video frames are not transmitted to external cloud APIs.
• Full-Stack Type Safety: Shared TypeScript contracts across frontend and backend,
  synchronized with PostgreSQL schemas via Prisma.

4. AI COMPUTER VISION SUBSYSTEM AUDIT (apps/ai-service - FastAPI)
================================================================================
Framework: FastAPI (Python 3.10+), ONNX Runtime, OpenCV, PyTorch, FAISS, HDBSCAN.

Biometric & Face Recognition Pipeline Trace:
1. Stage 1: Multi-Student Detection & Motion Tracking
   - SCRFD 10G: High-efficiency anchor-based face detection model providing 5-point
     facial landmarks and sub-pixel bounding box localization.
   - IoUTracker (apps/ai-service/app/services/face_tracker.py): Locked, zero-regression
     temporal tracker maintaining track continuity across 90-frame occlusions.

2. Stage 2: Face Quality Filtering Gate
   - MediaPipe Face Mesh: Evaluates 3D head pose (yaw, pitch, roll). Rejects samples
     exceeding 35° yaw or 25° pitch.
   - Laplacian Variance: Rejects blurred faces (variance < 25.0).
   - Resolution Gate: Requires minimum 20x20 bounding box dimensions.

3. Stage 3: Deferred ArcFace Batch Extraction
   - Model: ArcFace ResNet50 (512-dimensional output).
   - Normalization: Enforces strict L2 unit-norm normalization (||v|| = 1.0).

4. Stage 4: HDBSCAN Track-Level Clustering
   - Precomputes cosine distance matrix (1.0 - dot(C_i, C_j)).
   - Cluster selection epsilon calibrated to 0.20 (similarity >= 0.80).

5. Stage 5: Multi-Evidence Safe Identity Consolidation
   - Normal Merge Criteria (ALL must be satisfied):
     • Centroid Cosine Similarity >= 0.82
     • Representative Medoid Similarity >= 0.78
     • At least 3 independent sample pair comparisons >= 0.80
     • Top-4 cross-sample mean similarity >= 0.82
     • Anti-Contradiction: Min cross-sim >= 0.52 and Median cross-sim >= 0.68
     • Anti-Chaining: Min track-to-track centroid similarity >= 0.75
     • Zero contradictory enrolled FAISS identities.
   - High-Confidence Fallback Merge:
     • Centroid Similarity >= 0.80 AND >= 4 sample pairs >= 0.80 AND
       Top-4 Mean >= 0.82 AND Rep Sim >= 0.76 AND Min Track Sim >= 0.74.

6. Stage 6: Internal Cluster Purity Validation & Auto-Split
   - Evaluates connected components among member tracks at 0.76 similarity.
   - If multiple identity modes are discovered in a single cluster, the system
     automatically splits the cluster into pure sub-clusters and recomputes medoids.

7. Stage 7: FAISS Production Recognition Index
   - IndexFlatIP: Exact inner-product search over 512D normalized embeddings.
   - Recognition Threshold: 0.58 (Configurable in settings).

7. MATHEMATICAL MODELS & BIOMETRIC PIPELINE SPECIFICATION
================================================================================
1. ArcFace Angular Margin Loss:
   L = -log( e^{s * cos(theta_{y_i} + m)} / (e^{s * cos(theta_{y_i} + m)} + sum_{j != y_i} e^{s * cos(theta_j)}) )
   where s = 64.0 (scale), m = 0.50 (angular margin).

2. Cosine Similarity & Distance:
   S_C(u, v) = (u . v) / (||u||_2 * ||v||_2) = u . v  (for normalized vectors)
   D_C(u, v) = 1.0 - S_C(u, v)

3. Graph Connected Component Cluster Purity:
   For cluster C with member tracks T = {t_1, ..., t_m}:
   Adjacency A_{ij} = 1 if S_C(t_i, t_j) >= 0.76 else 0.
   Connected components {G_1, ..., G_k} = BFS(A).
   If k > 1: Split cluster C into {C_1, ..., C_k}.

================================================================================

   - Face embeddings are mathematical one-way projections (512 floats) and cannot
     be reverse-engineered to reconstruct the original human face photo.
   - Raw video footage is processed in ephemeral memory and discarded after feature
     extraction unless explicitly archived by institution policy.

2. Access Control & Tenant Isolation:
   - Every database query enforces tenant isolation via WHERE institutionId = :tenant.
   - API endpoints guarded by JwtAuthGuard, RolesGuard, and PermissionsGuard.

     attendance overrides, manual cluster assignments, and biometric resets.

9. END-TO-END EXECUTION WORKFLOWS
================================================================================
Workflow 1: Multi-Video Classroom Face Enrollment
1. Admin uploads 1-4 classroom video files (.mp4/.avi) in Face Enrollment Studio.
2. API creates EnrollmentJob record in PostgreSQL and dispatches job to AI Service.
3. AI Service processes video at 2 FPS:
   - SCRFD detects all candidate faces per frame.
   - FaceTracker associates detections into temporal tracks (Track IDs).
   - MediaPipe filters out blur, dark, and off-angle frames.
4. AI Service extracts 512D ArcFace embeddings for top quality samples per track.
5. HDBSCAN groups tracks into initial identity candidates.
6. Multi-Evidence Consolidation merges split tracks belonging to the same physical person.
7. Purity validation checks for multi-identity modes and auto-splits if necessary.
8. FAISS cross-references known database students.
9. Results saved to clusters.json and broadcast via WebSocket to the frontend dashboard.
10. Admin confirms or assigns clusters to registered students.

Workflow 2: Real-Time Lecture Attendance
1. Scheduled class session starts automatically based on Timetable.
2. AI Service connects to classroom RTSP camera stream.
3. Incoming frames undergo face detection and ArcFace feature extraction.
4. FAISS searches the 512D vector index:
   - If similarity >= 0.70 for >= 3 votes -> Mark student PRESENT (CONFIRMED).
   - If similarity between 0.58 and 0.70 -> Mark student CANDIDATE.
   - If no match -> Log to UnknownFace gallery.
5. AttendanceSession record updated in real-time on the Teacher & HOD dashboards.
